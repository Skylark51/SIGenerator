# SI Generator Native

## 구조 작업 화면과 SI 출력 개선 (2026-11-05)

- 구조 목록을 위쪽에 배치하고 반응 설정을 접을 수 있게 했습니다. 표시 열은 앱 설정에 저장되며 구조명은 항상 표시됩니다.
- **SPE 후보 찾기**에서 선택한 폴더의 Gaussian 출력 중 계산 접미사를 제외한 이름이 같은 파일을 검토합니다. 전하·multiplicity·원소 순서와 회전·이동 정렬 후 좌표를 검사하며, 정상 종료된 SPE 후보만 일괄 승인할 수 있습니다. 여러 후보가 있는 구조는 직접 선택합니다.
- 기존 -freq-bb 규칙은 검증을 통과한 연결에 계속 적용합니다. 이전 프로젝트에 저장된 연결은 검증 정보가 일부 빠져 있으면 경고와 함께 복원합니다. 전하·multiplicity 또는 구조 불일치가 확인된 SPE는 에너지와 스핀에서 제외합니다.
- 자동 상대에너지의 엔트로피 항은 Gaussian 온도를 사용합니다. 온도가 생략된 기존 출력은 298.15 K를 사용하고, 온도가 다른 구조 간 엔트로피 항과 ΔG 차이는 N/A로 표시합니다.
- Word 출력에서 Figure의 분자당 배율과 라벨 크기를 통일했습니다. 표의 셀 데이터와 캡션은 유지하고 모든 셀을 가운데 정렬했습니다. 반복 헤더, 행 나눔, 캡션과 각주 간격도 조정했습니다. 좌표는 6pt와 기존 자릿수를 유지하며 XYZ를 탭으로 정렬합니다.


`SIGenerator.exe`를 이 폴더에서 바로 실행합니다. Python 설치는 필요하지 않습니다.
Windows GUI 실행 파일로 빌드되어 DOS/콘솔 창 없이 실행됩니다.
시작 시 앱 아이콘이 담긴 스플래시 화면을 표시하고, 초기 준비 및 약 0.24초의 사라지는 전환 효과를 포함해 약 2초 후 프로젝트 관리 창을 엽니다.

Table 캡션은 번호 필드의 코드와 결과를 모두 볼드체로 지정해 Word에서 필드를 갱신한 뒤에도 `Table S10` 등의 숫자가 볼드체를 유지합니다.
상대에너지 각주 c는 `E_Total`부터 `ΔG` 앞까지 실제로 더하는 열만 셉니다.
dispersion·complexation을 모두 제외하면 4개, 하나만 포함하면 5개, 둘 다 포함하면 6개이며 미리보기와 DOCX에 같은 설명을 사용합니다.
Computational Details 입력 앞에 붙여넣은 제목이 있으면 출력 시 제목을 중복 표시하지 않습니다.

특정 반응 단계의 구조만 보정하려면 해당 단계를 선택하고 구조 목록에서 대상 구조를 선택한 뒤
`선택 구조의 상대 에너지·열역학 입력…`을 누릅니다. 상대 에너지 성분, ZPE·열 보정,
−TΔS, ΔG를 kcal/mol로 입력할 수 있습니다. 입력한 칸만 해당 단계·구조에 적용하며,
빈칸은 자동값을 유지합니다. ΔG를 비우면 ETotal과 열역학적 성분 및 선택된 추가 보정을 합산합니다.
원자 수가 기준 구조와 다르면 빈칸은 N/A로 표시하며, ΔG 또는 합산에 필요한 모든 성분을 입력해야 합니다.
구조별 입력 모드와 값은 프로젝트에 저장되며, 구조 순서·이름을 바꿔도 같은 파일에 연결됩니다.
기존의 단계 전체 ΔG 입력 방식도 계속 사용할 수 있습니다.

Selected Geometry의 원자 ID를 비워 두면 비교 가능한 구조를 회전·이동 정렬한 후,
원자별 RMS 변위와 거리 변화로 반응 좌표 후보를 최대 6개 자동 표시합니다.
원자 수·원소 순서가 같고 원자 번호가 서로 대응하는 구조가 2개 이상 필요합니다.
첫 비교 구조 기준 RMSD를 표시합니다. H–H(수소 동위원소 포함)는 자동 후보에서 제외합니다.
후보는 적어도 한 구조에서 공유 반지름 합의 1.25배 이내에 들어오는 원자쌍 중,
거리 변화가 0.15 Å 이상, 정렬 후 원자 RMS 변위가 0.03 Å 이상인 쌍입니다.
6 Å 이상 떨어진 적이 있는 원자쌍은 최소 거리가 2 Å 이하인 경우에만 허용합니다.
결합 거리 경계를 넘는 형성·절단 후보를 우선하며, 그 안에서는
(거리 변화 / 결합 거리 기준) × 두 원자의 RMS 변위 합으로 순위를 정합니다.
기준을 충족하는 후보가 없으면 자동 표를 만들지 않습니다.
비교 불가능한 구조는 자동 분석에서 제외하고 표에는 N/A를 표시합니다.
직접 입력한 2/3/4개 원자 ID(거리/각/이면각)는 자동 분석보다 우선합니다.

미리보기에서 표를 선택하면 `선택 표 복사 (Copy Table)`로 Word/Excel용 표를,
`표 이미지 복사 (Copy Image)`로 투명 배경 PNG를 클립보드에 복사할 수 있습니다.
이미지에는 캡션·각주·바깥 여백 없이 표만 포함되며, 화면 밖의 행도 모두 복사됩니다.
표의 상단·헤더 아래·하단 가로선은 모두 0.75 pt로 통일됩니다.
표의 제목·구조명·숫자는 각 셀 안에서 한 줄로 표시합니다. 넓은 표는 미리보기에서
가로 스크롤하며, 이미지 복사는 필요한 전체 너비를 사용합니다.

폴더 지정과 폴더 드롭은 기본 경로만 설정하며, 폴더 안의 파일과 하위 폴더를 자동으로 읽지 않습니다.
파일 추가·파일 드래그앤드롭·파일명으로 추가는 기존 구조 목록 뒤에 선택한 파일을 누적합니다.
이미 등록된 파일은 중복 추가하지 않으며, 해석 중 추가한 파일도 순서대로 처리합니다.
프로젝트 열기는 저장된 프로젝트의 구조 목록으로 교체합니다.

엑셀에 정리한 파일명은 다음 순서로 가져옵니다.
1. `폴더 지정 (Set Folder)`으로 파일이 있는 기본 폴더를 선택합니다.
2. 엑셀에서 파일명 셀들을 복사한 뒤 파일명 입력칸에 `Ctrl+V`로 붙여넣습니다.
3. `파일명으로 추가 (Add by Names)`를 누릅니다.

여러 행·열의 셀(줄바꿈·탭)을 지원하며, 셀 하나에 파일명 하나를 입력합니다.
`.out`·`.log`는 생략할 수 있습니다. 같은 이름의 두 확장자가 모두 있으면 확장자를 지정해야 합니다.
한글·공백이 있는 파일명과 기본 폴더 기준 상대 경로도 사용할 수 있습니다.
찾지 못한 이름은 입력칸 아래에 표시하고, 찾은 파일부터 추가합니다.

`구조명<Tab>파일명` 두 열을 함께 붙여넣으면 왼쪽 셀을 구조명으로 사용합니다.
`1CP1-2`, `5CP1-2`, `1-CP1-2`, `1CP1-2-TS`처럼 하이픈으로 번호를 구분한 이름도 지원합니다.
`입력 목록으로 교체`는 입력한 라벨과 파일 순서를 그대로 반영하며, 기존 파일명 표시도 지정한 라벨로 바꿉니다.
`SI DOCX 생성`을 누를 때도 붙여넣기 입력란의 라벨을 현재 불러온 파일에 다시 적용합니다.
이미 불러온 구조의 이름만 갱신하므로 사용자가 정한 목록 순서와 파싱된 스핀 데이터는 유지됩니다.

파일 추가·드롭으로 `이름-ts-freq.out` 하나만 추가하면 같은 폴더에 있는
`이름-ts-freq-ircfwd-opt-freq.out`과 `이름-ts-freq-ircrev-opt-freq.out`도 함께 가져옵니다.
`.log`도 같은 규칙을 사용합니다. 없는 IRC 파일은 완료 메시지에 표시합니다.
목록의 `위로`·`아래로`·`위치 지정` 버튼으로 구조 순서를 변경하면 표와 출력에도 반영됩니다.
TS와 각 IRC 구조의 스핀은 각각 대응하는 `-freq-bb.out`(또는 `.log`)에서 우선 가져옵니다.
`-bb`에 유효한 스핀이 없으면 기존 주 파일 스핀 fallback을 유지합니다.
프로젝트를 다시 열 때는 저장된 구조 목록과 순서를 그대로 복원하며 IRC 파일을 새로 추가하지 않습니다.

Ctrl+O / 파일 메뉴의 Gaussian 파일 열기는 Gaussian 파일을 추가합니다.
저장된 JSON 프로젝트는 별도의 프로젝트 열기를 사용합니다.
선택한 파일은 목록에 즉시 나타나며, 백그라운드 해석 결과가 파일별로 표시됩니다.
해석 중 프로젝트를 열면 이전 해석과 대기 요청을 취소하고 새 프로젝트로 교체합니다.
파일 선택 창은 Qt 대화상자를 사용합니다.

2026-10-26 가져오기 수정 검증: Gaussian/문서/UI 회귀 검사 3종 통과.
20 MiB 합성 출력의 cold parse는 같은 환경에서 약 1.50초 → 0.18초로 개선됐습니다.
UI 검사는 한글 파일명, 즉시 목록 표시, 해석 중 이벤트 처리, 연속 추가,
프로젝트 교체, 폴더 지정 시 파일 미추가, 파일 대화상자 선택, 해석 중 창 종료를 포함합니다.

## 폴더 구성

- `SIGenerator.exe`: 실행 파일
- `Qt6*.dll`, `D3Dcompiler_47.dll`, `platforms/`, `styles/`: 실행에 필요한 Qt 런타임
- `native/`: C++20/Qt6 소스
- `tests/fixtures/`: 네이티브 회귀 테스트용 최소 Gaussian fixture
- `CMakeLists.txt`, `CMakePresets.json`: 빌드 설정

## Release 빌드

Qt 6.5 이상과 Visual Studio 2022 C++ 도구가 필요합니다.

```powershell
$env:CMAKE_PREFIX_PATH = "C:\Qt\6.x.x\msvc2022_64"
cmake --preset windows-msvc-release
cmake --build --preset windows-msvc-release
```

Release 빌드가 성공하면 `SIGenerator.exe`가 이 프로젝트 루트에 생성됩니다.
Qt 런타임을 다시 배치하려면 `SI_GENERATOR_QT_BIN`을 설정한 뒤 `native\deploy.ps1`을 실행합니다.

이전 Python 구현과 과거 산출물은 상위 `이전 파일 백업` 폴더에 보관합니다.

## 분자 Figure와 SI DOCX 구성 (2026-10-27)

`문서와 출력`의 `분자 Figure 뷰 설정`에서 첫 3개(왼쪽 IRC–TS–오른쪽 IRC),
이후 새 구조 2개씩 뷰를 확인합니다. Generate SI를 누르면 매번 렌더링 포함 여부를 묻습니다.
`렌더링 포함`을 선택하면 이 창에서 Figure를 준비합니다.
`Figure 없이 표만 생성`을 선택하면 렌더링 창을 건너뛰고 Figure와 Figure 캡션 없이
표를 생성합니다. 기존 계산 설명·문헌·Cartesian Coordinates는 유지합니다.
이전에 준비한 Figure가 있어도 표만 생성한 문서에는 포함하지 않습니다.
구조 선택 상자는 전체 목록에서 위치를 교환하며, 중복이나 누락 없이 배치합니다.
맨 마지막에 구조가 하나만 남으면 해당 구조도 출력합니다.

왼쪽 드래그로 회전, Alt+드래그로 화면 안 회전, 오른쪽 드래그로 이동,
휠로 확대합니다. `카메라 함께 회전`을 해제하면 각 구조를 개별 조정합니다.
`TS 기준 정렬 및 뷰 맞추기`는 원자 순서와 원소가 대응하는 구조를
비수소 원자 중심으로 강체 회전 정렬합니다. 대응하지 않으면 안내 후 직접 조정합니다.
테두리 안의 영역이 분자 이미지에 대응하며, 원본 좌표는 변경하지 않습니다.

Figure 창은 Youngcraft의 현재 저장 스타일을 읽습니다. 원소별 RGB,
혼합/단일/원자별 결합색, 원자·결합 크기, 채도, 밝기·광택 설정을 적용합니다.
Youngcraft의 설정은 읽기만 하며 수정하지 않습니다. Figure 창을 새로 열면
최신 저장 스타일을 다시 읽습니다. 뷰·배치·렌더링 설정은 프로젝트에도 저장합니다.
렌더링은 SI Generator의 고해상도 구·결합 렌더러를 사용하며 Youngcraft의
OpenGL 그림자 엔진 전체를 포함하지는 않습니다.

SI DOCX는 다음 순서입니다.
1. 첫 페이지: Computational Details와 입력한 SI References
2. 분자 Figure (고해상도 투명 PNG를 DOCX 내부에 포함)
3. Absolute Energy table (체크했을 때만, 새 프로젝트에서는 기본 해제)
4. Relative Energy table
5. Mulliken Spin Density table
6. Selected Geometry table
7. 마지막 섹션: 전체 구조 이름과 Cartesian Coordinates (기존 좌표 형식 유지)

References는 직접 입력하거나, `출판 논문 계산 문헌 S24–S29 선택·추가`에서 내장 문헌을 선택합니다.
Computational Details와 References가 비어 있어도 SI DOCX를 생성할 수 있습니다.
스핀/선택 구조 표는 기존 방식대로 추출 데이터 또는 직접 지정한 원자 ID로 만듭니다.
Figure 캡션은 구조당이 아니라 Figure 그룹당 한 줄입니다.

네이티브 Gaussian·DOCX·UI 회귀 검사에 3→2→2 Figure 생성, 카메라 공유/독립 조정,
배치 교환, 프로젝트 복원, 저장된 Youngcraft RGB와 조명값 일치 검증을 포함합니다.
`tools/verify_si_docx.py`로 검사 DOCX의 XML·CRC·내장 이미지와 섹션 순서를 확인할 수 있습니다.

## 라벨과 파일명을 함께 입력하기

파일명 입력칸에 엑셀의 `라벨링`·`파일이름` 두 열을 그대로 붙여넣은 뒤
`파일명으로 추가`를 누릅니다. 괄호는 필요하지 않습니다.
`(라벨링 파일이름)` 형식도 계속 지원합니다.
기존의 파일명만 입력하는 방식과 함께 사용할 수 있습니다.

```text
(1C calculation_a.out)
(3DRC calculation_b)
(5DCR-TS "공백이 있는 계산 파일.out")
```

여러 행·탭과 한 셀 안의 여러 괄호 쌍을 지원합니다. 파일명 안의 괄호와
확장자 생략 규칙도 유지됩니다. 이미 추가된 파일에 라벨을 지정하면
중복으로 추가하지 않고 해당 구조 이름을 갱신합니다.

숫자로 시작하는 구조명의 맨 앞 숫자는 multiplicity 위첨자로 표시합니다.

앱 아이콘은 내장 ImageGen으로 생성했으며 원본 PNG·여러 해상도의 ICO·제작 프롬프트를 native/resources에 보관합니다.
Windows 실행 파일의 아이콘과 앱 창 아이콘에 내장했습니다.

검증: Release 빌드, Gaussian·DOCX·UI 회귀 검사 3종 통과.
UI 검사에 반응별 순서 분리·현재/전체 미리보기·공통 구조명·배정 제외·기존 파일 재배정·대기 요청의 반응 유지·
선택형 추출 정보·반응별 Figure 구성과 DOCX 배치·프로젝트 저장 및 복원을 포함합니다.

## UI 작업 영역 개편 (2026-11-02)

- 오른쪽 **3D 분자 뷰어 / SI 문서 미리보기**를 탭으로 전환합니다. 한 번에 한 화면에 넓은 공간을 배정합니다.
- 오른쪽 위 **크게 보기**는 반응 탐색기와 입력 영역을 접어 뷰어를 확대합니다. **기본 화면**을 누르면 기존 분할 상태로 돌아갑니다.
- 현재 반응 구조 목록에서 `구조명 | Output 파일 | M | Freq | SPE | Imag | 상태`를 확인합니다. 상태에 마우스를 올리면 기존 검증 경고가 표시됩니다. 반응 단계 일괄 편집창은 기존의 2열 엑셀 붙여넣기 방식을 유지합니다.
- 상단 툴바는 파일/설정/분자/내보내기로 묶고 **파일 추가**, **저장**, **SI 생성**에는 텍스트를 표시합니다. 설정 아이콘과 Alt+1~5 단축키는 그대로 사용합니다.

## GitHub에서 기존 로컬 EXE 자동 업데이트 (2026-11-02)

소스 코드를 동기화하는 `git pull`만으로는 실행 파일이 갱신되지 않습니다. `SIGenerator.exe`와 Qt DLL은 Git 추적에서 제외하고, GitHub Actions에서 따로 빌드합니다.

**처음 한 번만** Windows에서 GitHub CLI를 설치하고 로그인합니다.

```powershell
winget install --id GitHub.cli -e
gh auth login
```

이후에는 프로그램을 종료한 뒤 **기존 SI_Generator_Project 폴더**에서 아래 두 명령을 실행합니다.

```powershell
git pull --ff-only origin main
.\native\update-local.ps1
```

스크립트는 로컬 커밋과 **정확히 일치하는 main 브랜치의 성공한 Windows 빌드**를 GitHub Actions에서 찾습니다. 배포 패키지는 임시 폴더에 다운로드하고, EXE와 Qt 런타임을 원래 프로젝트 폴더에 설치합니다. 기존 실행 파일은 `backups/runtime-날짜`에 백업하며 임시 ZIP은 작업이 끝나면 삭제합니다. `Downloads` 폴더에 ZIP을 수동으로 저장할 필요가 없습니다.

아직 해당 커밋의 Windows 빌드가 완료되지 않았거나 실패한 경우 업데이트를 중지하고 안내합니다. 이미 내려받은 ZIP을 사용할 때만 `-PackagePath "실제 ZIP 경로"`를 명시합니다.

## Windows 실행 파일 빌드와 배포

Qt 6.8.3 MSVC 2022 x64 및 Visual Studio 2022 C++ 빌드 도구가 필요합니다. PowerShell에서 저장소 루트로 이동하여 다음을 실행합니다.

```powershell
.\native\build-release.ps1 -QtRoot "C:\Qt\6.8.3\msvc2022_64"
```

스크립트는 Release 빌드, CTest 회귀 검사, `windeployqt` 런타임 배치 후 `SI-Generator-Windows-x64.zip`을 생성합니다. 압축을 풀어 같은 폴더의 `SIGenerator.exe`를 실행하세요. 새 버전으로 패치할 때는 프로그램을 종료하고 **새 ZIP의 내용을 통째로 덮어쓰기** 하면 됩니다. 앱의 사용자 프로젝트 `.si_project.json`과 Gaussian 원본 파일은 배포 폴더 외부에 보관하는 것이 안전합니다.

GitHub Actions의 **Windows release build** 워크플로는 `main` 업데이트와 PR에서 자동 빌드·테스트합니다. 성공하면 해당 실행의 **Artifacts → SI-Generator-Windows-x64**에서 ZIP을 받을 수 있습니다. `v*` 태그를 푸시하면 검증 후 GitHub Release에도 ZIP을 첨부합니다.

```powershell
git add native/src .github/workflows native/build-release.ps1 README.md .gitignore
git commit -m "Improve UI and Windows distribution"
git push origin main

# 배포 버전을 고정할 때 (중복되지 않는 버전 번호 사용)
git tag v0.2.0
git push origin v0.2.0
```

소스 및 빌드 설정만 Git으로 커밋합니다. `dist/`, `*.exe`, 배포 ZIP은 `.gitignore`에 의해 추적되지 않으며 GitHub Actions Artifacts 또는 Releases로 제공합니다.


## 원본 Gaussian 파일 없이 프로젝트 이동·재생성 (프로젝트 v8)

Gaussian `.out`/`.log`를 불러와 해석을 완료한 뒤 **프로젝트 저장(Ctrl+S)** 을 실행하면
SI 생성에 사용하는 추출값을 `.si_project.json` 안에 압축하여 포함합니다.
전자에너지, 열역학 보정값, 스핀 밀도, 선택 좌표, 원자 정보, 계산 조건, 허수 진동수 및
연결된 `-freq-bb` SPE 데이터가 보존됩니다. 원본 Gaussian 출력 텍스트는 포함하지 않습니다.

이후에는 다른 컴퓨터에서 **프로젝트 JSON 파일 하나만 열어도** 구조 목록, 반응 단계,
에너지·스핀·기하 정보 및 SI 문서 생성을 다시 사용할 수 있습니다. 프로젝트를 열 때
저장된 스냅샷을 우선 사용하므로 기존 경로에 원본 `.out`이 존재하지 않아도 됩니다.
구조별 연결 원본 경로는 식별용으로 남지만 데이터를 읽는 데 필요하지 않습니다.

**이전 버전 프로젝트**에는 추출값이 저장되지 않았습니다. 최초 한 번 원본 Gaussian
파일이 있는 컴퓨터에서 해당 프로젝트를 열어 파일들을 불러온 뒤 새 버전으로 저장해야 합니다.
이미 원본 파일을 분실한 과거 프로젝트에서는 추출 데이터를 복구할 수 없습니다.
프로젝트 파일은 실제 데이터가 포함되므로 공유 시 계산 결과의 공개 여부를 확인하세요.

### 기존 설치 경로에서 Windows 실행 파일 업데이트

실행 파일과 Qt DLL은 계속 원래 프로젝트 루트에서 실행합니다. Git으로 추적하지 않는
`SIGenerator.exe`를 `git pull`로 생성할 수는 없습니다. **GitHub Actions → Windows release build →
Artifacts → SI-Generator-Windows-x64**의 압축 파일을 다운로드한 뒤 앱을 종료하고 다음을 실행하세요.

```powershell
cd "D:\이영섭\프로젝트 개발\개발프로젝트\SI_generator_관련\SI_Generator_Project"
.\native\update-local.ps1 -PackagePath "$env:USERPROFILE\Downloads\SI-Generator-Windows-x64.zip"
.\SIGenerator.exe
```

이 스크립트는 일반 배포 ZIP과 GitHub Actions의 중첩 ZIP을 모두 처리하며 EXE·DLL·Qt
플러그인을 **기존 프로젝트 루트에 덮어씁니다**. 교체 대상이던 파일은
`backups/runtime-YYYYMMDD-HHMMSS`에 백업합니다. CMake 소스와 사용자 프로젝트 JSON은
건드리지 않습니다. 이 스크립트는 사용자의 Windows 컴퓨터에서 직접 실행해야 합니다.
